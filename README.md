## 🌟 О проекте

При использовании **BorgBackup** на домашних и офисных серверах (OpenMediaVault, Debian, Ubuntu, TrueNAS) администраторы часто сталкиваются с дилеммой:
1. **BorgWarehouse** спроектирован как централизованный сервер резервного копирования для внешних клиентов по SSH, и его сложно органично подключить к существующим *локальным* репозиториям на дисках сервера.
2. **Prometheus + Borg-Exporter + Grafana** дает отличную аналитику, но потребляет 300–500 МБ оперативной памяти ради мониторинга пары репозиториев.
3. **Стандартная консоль** (`borg info / list`) не дает наглядной картины динамики роста данных, эффективности дедупликации и времени выполнения по дням.

**BorgBackup Analytics Dashboard** решает эту проблему:
* Работает прямо с локальными репозиториями на дисках без необходимости проксирования через SSH.
* Потребляет всего **~50 МБ RAM** и **0.1% CPU**.
* Отдает готовый интерфейс и метрики за **~9 миллисекунд** благодаря двухуровневому кэшированию метаданных.
* Предоставляет детальные интерактивные графики, генератор команд восстановления и мониторинг полного контура **3-2-1**.

## 🚀 Основные возможности

### 1. 📊 Сводные KPI и аналитика эффективности
* **Всего под защитой (Raw Data):** Суммарный объем файлов во всех архивах (например, `2.95 ТБ`).
* **Реальный размер на диске:** Объем уникальных сжатых чанков, занимаемый на физическом накопителе (например, `132.8 ГБ`).
* **Коэффициент экономии места:** Наглядный мультипликатор сжатия и дедупликации (например, **`22.3x`** / **`-95.5%`**).
* **Счетчик архивов:** Общее количество доступных точек восстановления.

### 2. 📈 Интерактивные графики (ApexCharts)
* **Прирост новых данных (Инкременты):** Наглядный бар-чарт, показывающий в МБ/ГБ, сколько уникальных данных записал каждый ночной срез.
* **Длительность выполнения бэкапов:** График времени создания снимков (в секундах), позволяющий вовремя обнаружить просадки скорости диска или сети.
* **Фильтрация по репозиториям:** Переключение между общим срезом и отдельными репозиториями в 1 клик.

### 3. 🛡️ Мониторинг контура 3-2-1
Визуальные бейджи со статусами и временем последнего выполнения смежных подсистем:
* **Проверка целостности (`borg check`):** Отслеживание результатов плановых тестов репозиториев и наличия ошибок.
* **Синхронизация с облаком:** Статус ночной выгрузки в Яндекс.Диск / S3 / Mail.ru (через `rclone`).
* **Пре-дампы баз данных:** Контроль создания горячих дампов (PostgreSQL, SQLite, Paperless, Authentik, Vaultwarden).
* **Холодные оффлайн-копии:** Статус еженедельных аппаратных снимков (rsync hardlinks).

### 4. 📋 Журнал архивов (Archive Explorer)
* Удобная таблица всех точек восстановления с фильтрами и мгновенным поиском по имени или дате.
* **Генератор команд восстановления (CLI Helper):** Кнопка у каждого архива генерирует готовые команды с подставленными путями и архивом для копирования в буфер:
  * `borg mount /путь::архив /mnt/borg` (FUSE-монтирование для просмотра файлов через проводник)
  * `borg extract /путь::архив path/to/file` (быстрое извлечение конкретного файла)
  * `borg break-lock /путь` (снятие зависшей блокировки)
  * `borg check --prefix архив /путь` (выборочная проверка целостности архива)

### 5. ☀️ / 🌙 Светлая и тёмная темы
* Полноценная светлая тема (высокая контрастность, чистые карточки, идеальная читаемость днем).
* Глубокая тёмная тема в стиле современного homelab-софта (Beszel, Dozzle).
* Переключатель тем в шапке с сохранением выбора в `localStorage`.

### 6. 📖 Интегрированная инструкция по аварийному восстановлению (DR)
* Прямо в интерфейсе по кнопке открывается полное руководство по восстановлению данных сервера (Markdown-документ) с оглавлением, таблицами и командами.

## 📦 Быстрый старт (Docker Compose)

### 1. Клонируйте репозиторий:
```bash
git clone https://github.com/scanek/borg-dashboard.git
cd borg-dashboard
```

### 2. Настройте `docker-compose.yml`:
Укажите пути к вашим существующим репозиториям Borg и каталогу логов:

```yaml
services:
  borg-dashboard:
    build: .
    image: borg-dashboard:latest
    container_name: borg-dashboard
    restart: unless-stopped
    network_mode: host
    environment:
      - TZ=Europe/Moscow
      - BORG_UNKNOWN_UNENCRYPTED_REPO_ACCESS_IS_OK=yes
      - BORG_RELOCATED_REPO_ACCESS_IS_OK=yes
      - BORG_CACHE_DIR=/tmp/borg_cache
    volumes:
      # Репозитории Borg на вашем сервере
      # (Borg создает кратковременный lock-файл при чтении, поэтому требуется доступ на запись)
      - /srv/dev-disk-by-uuid-xxx/borg_backup:/repos/borg_backup
      - /srv/dev-disk-by-uuid-xxx/backups/immich-borg:/repos/backups/immich-borg
      # Логи резервного копирования (read-only)
      - /volume1/logs:/logs:ro
      # Инструкция по восстановлению (read-only, опционально)
      - /volume1/script/ИНСТРУКЦИЯ_ПО_ВОССТАНОВЛЕНИЮ.md:/app/docs/RECOVERY.md:ro
      # Сохранение кэша между перезапусками контейнера
      - ./data:/app/data
    healthcheck:
      test: ["CMD", "python3", "-c", "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8099/api/health')"]
      interval: 30s
      timeout: 10s
      retries: 3
```

### 3. Запустите контейнер:
```bash
docker compose up -d --build
```

Откройте в браузере: **`http://<IP-вашего-сервера>:8099`**.

## ⚙️ Конфигурация нескольких репозиториев

Вы можете легко настроить произвольное количество репозиториев через файл `config.json` (в корне проекта или в каталоге `data/config.json`):

```json
[
  {
    "id": "docker",
    "name": "Docker & Контейнеры",
    "path": "/repos/borg_backup",
    "host_path": "/srv/dev-disk-by-uuid-xxx/borg_backup",
    "source": "/volume1/docker",
    "schedule": "Ежедневно в 01:00",
    "description": "Контейнеры, базы данных, пре-дампы и конфигурации"
  },
  {
    "id": "photos",
    "name": "Семейный фотоархив",
    "path": "/repos/backups/photos-borg",
    "host_path": "/srv/dev-disk-by-uuid-xxx/backups/photos-borg",
    "source": "/volume1/photos",
    "schedule": "Ежедневно в 00:30",
    "description": "Медиатека фотографий и видео"
  }
]
```

## 🔌 Интеграция с домашней экосистемой

### 1. OliveTin (`:1337`)
В панель **OliveTin** добавляется кнопка внеочередной проверки целостности:
```yaml
  - title: "Проверка целостности Borg"
    icon: '<svg xmlns="http://www.w3.org/2000/svg" width="24" height="24" viewBox="0 0 24 24"><path fill="#10b981" d="M12 1L3 5v6c0 5.55 3.84 10.74 9 12c5.16-1.26 9-6.45 9-12V5l-9-4zm-2 16l-4-4l1.41-1.41L10 14.17l6.59-6.59L18 9l-8 8z"/></svg>'
    shell: "nsenter -t 1 -m -u -i -n -p -- /volume1/script/check_borg_repos.sh"
    timeout: 3600
```

### 2. Uptime Kuma (`:3002`)
Контейнер поддерживает эндпоинт `/api/health`, который можно подключить как стандартный HTTP-монитор в **Uptime Kuma** для отслеживания доступности дашборда.

## 📡 API Эндпоинты

| Метод | Эндпоинт | Описание |
|---|---|---|
| `GET` | `/` | Главная страница аналитики (HTML) |
| `GET` | `/api/status` | Полная сводка метрик, репозиториев, архивов и здоровья контура в JSON |
| `POST`| `/api/refresh`| Принудительный запуск фонового обновления кэша |
| `GET` | `/api/health` | Проверка жизнеспособности сервиса (`{"status": "ok"}`) |
| `GET` | `/api/guide` | Текст руководства по восстановлению (Markdown) |
