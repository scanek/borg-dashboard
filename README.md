## 🌟 О проекте

При эксплуатации **BorgBackup** на домашних и офисных серверах (OpenMediaVault, Debian, Ubuntu, Proxmox, TrueNAS) администраторы часто сталкиваются со следующими сложностями:
1. **BorgWarehouse** спроектирован как централизованный сервер резервного копирования для внешних клиентов по SSH, и его сложно органично подключить к существующим *локальным* репозиториям на дисках сервера.
2. **Prometheus + Borg-Exporter + Grafana** дает аналитику, но потребляет 300–500 МБ оперативной памяти только ради наблюдения за парой репозиториев.
3. **Стандартная консоль** (`borg info / list`) не дает визуальной картины динамики роста данных, дедупликации и истории срезов.
4. **Настройка новых бэкапов** обычно требует написания shell-скриптов или ручной настройки cron-файлов на хосте.

**BorgBackup Analytics Dashboard** объединяет в себе:
* **Мониторинг и глубокую аналитику** локальных репозиториев без проксирования через SSH.
* **Интерактивный центр управления задачами**: выбор каталогов сервера через визуальный проводник, гибкая настройка политик ротации (retention/prune), шаблонов исключений и расписания.
* **Встроенный терминал действий в реальном времени**: выполнение `create`, `check`, `prune`, `compact` с живой трансляцией вывода консоли по протоколу Server-Sent Events (SSE).
* **Проводник файлов срезов и прямое скачивание**: просмотр файлов внутри исторических архивов и мгновенная выгрузка нужных файлов в браузере.
* **Экстремальную легковесность**: потребляет всего **~50 МБ RAM** и практически **0% CPU** в режиме ожидания.
* **Высокую скорость**: отдача главной страницы и сводки метрик за **~5–10 миллисекунд** благодаря умному кэшированию.

## 🚀 Основные возможности

### 1. 📊 Сводные KPI и аналитика эффективности
* **Всего под защитой (Raw Data):** Суммарный объем файлов во всех снимках до сжатия и дедупликации (например, `3.2 ТБ`).
* **Реальный размер на диске:** Физический объем уникальных сжатых блоков (чанков) в репозитории (например, `145 ГБ`).
* **Коэффициент экономии места:** Наглядный множитель эффективности дедупликации (например, **`22.3x`** / **`-95.5%`** сэкономленного пространства).
* **Счетчик архивов:** Общее количество доступных точек восстановления.
* **Срок службы диска (Storage Runway):** Интеллектуальный прогноз исчерпания свободного места на диске на основе среднемесячного темпа прироста данных (например, `> 10 лет` или `14 мес.`).

---

### 2. 🗂️ Серверный проводник и визуальный выбор источников (`/api/fs/browse`)
Больше не нужно вручную вспоминать и прописывать длинные пути к томам и контейнерам:
* Встроенный файловый браузер позволяет визуально перемещаться по разделам сервера:
  * `/srv/...` (физические накопители, разделы по UUID).
  * `/volume1/...` (пулы данных, каталоги Docker-контейнеров, медиатеки).
* Навигация с хлебными крошками (breadcrumbs) и переход на уровень вверх.
* Добавление папки в список бэкапа в один клик кнопкой **`+ Выбрать`**.
* **Абсолютная безопасность хоста**: разделы сервера монтируются в контейнер дашборда в режиме **`ro` (read-only)** — создание бэкапа гарантированно не может повредить или удалить рабочие файлы на хосте.

---

### 3. ⚙️ Интерактивный конфигуратор задач бэкапа (Backup Job Manager)
Создание и редактирование резервных копий прямо из браузера:
* **Параметры архивации**:
  * Имя задачи (например, *«Конфиги Docker»*, *«Immich Фотоархив»*).
  * Выбор целевого репозитория Borg.
  * Префикс имени архива (автоматически формируется имя вида `{prefix}-YYYY-MM-DD_HH-MM-SS`).
  * Произвольный список источников (папки или отдельные файлы).
* **Шаблоны исключений (Excludes)**:
  * Быстрые чекбоксы для стандартного серверного «мусора»: временные файлы `*.tmp`, сокеты `*.sock`, кэши `*cache*`, логи `*.log`.
  * Поле для ввода пользовательских масок (например, `thumbs`, `encoded-video`, `node_modules`).
* **Алгоритмы сжатия**:
  * `auto,zstd,6` — рекомендуемый баланс высокой степени сжатия и умеренной нагрузки на CPU.
  * `lz4` — ультрабыстрое сжатие для слабых процессоров или гигабитных потоков.
  * `auto,zlib,9` — максимальное сжатие для архивных копий.
  * `none` — без сжатия (для уже сжатых медиафайлов).
* **Политика ротации (Retention / Prune)**:
  * Хранить ежедневных копий (`keep-daily`, например, 7).
  * Хранить еженедельных копий (`keep-weekly`, например, 4).
  * Хранить ежемесячных копий (`keep-monthly`, например, 3).
* **Расписание автозапуска**:
  * Встроенный фоновый планировщик: ежедневно в заданное время, по выбранным дням недели или только ручной запуск.
* **Опция Compact**:
  * Возможность включить `compact` после выполнения задачи (по умолчанию отключена, что гарантирует сверхбыстрое выполнение ежедневных инкрементов за 1–3 секунды даже на больших HDD-репозиториях).

---

### 4. ⚡ Живой терминал и запуск действий в реальном времени (Live SSE Terminal)
* Запуск задач бэкапа и сервисных операций «в один клик».
* Потоковая трансляция стандартного вывода (stdout/stderr) команд Borg в веб-интерфейс без перезагрузки страницы по протоколу **Server-Sent Events (SSE)**.
* Цветовая подсветка строк: синтаксис команд `$`, информационные сообщения `---`, предупреждения `WARNING` (жёлтый) и ошибки `ERROR` (красный).
* **Доступные быстрые действия**:
  * `Запустить задачу сейчас` — последовательное выполнение `borg create` -> `borg prune` -> опциональный `borg compact`.
  * `Проверить целостность (borg check)` — плановая проверка репозитория.
  * `Снять блокировку (borg break-lock)` — быстрое снятие зависшего lock-файла после аварийного отключения питания или сбоя сети.
  * `Оптимизировать хранилище (borg compact)` — высвобождение места после удаления старых срезов.
  * `Обновить кэш данных` — немедленный сбор свежих метаданных со всех репозиториев.

### 5. 📅 Интерактивный журнал архивов: Календарь + Таблица с пагинацией и сортировкой
Журнал архивов предоставляет два взаимосвязанных режима отображения для максимального удобства мониторинга и навигации по срезам:

* **Переключатель режимов `[ Таблица ]` ↔ `[ Календарь ]`**:
  * Мгновенное переключение контекста в шапке блока в один клик.

* **Режим «Календарь» (Calendar View)**:
  * **Месячная сетка (Пн–Вс)** с удобными кнопками перелистывания месяцев (`« Предыдущий`, `Следующий »`) и быстрым возвратом к кнопке `Сегодня`.
  * **Цветные чипы бэкапов в ячейках дней**:
    * 🔵 **Docker**: время снимка (`01:00`) и объем записанных новых данных (`+2.4 МБ`).
    * 🟢 **Immich**: время снимка (`00:30`) и дельта дедупликации (`+15.8 МБ`).
    * Текущая дата выделена бейджем `Сегодня`.
  * **Интерактивная панель дня**:
    * Клик по любому дню выделяет его рамкой и открывает под календарём подробную карточку всех срезов за эту дату.
    * Быстрые действия у каждого среза: **`[ 📂 Файлы ]`** (проводник с прямым скачиванием) и **`[ 💻 Команды ]`** (CLI-команды восстановления).
    * Кнопка **`[ Показать в таблице ]`** — переключает в табличный вид с сохранением фильтра по выбранному дню.

* **Режим «Таблица» с пагинацией и сортировкой (Table View)**:
  * **Постраничный просмотр (Pagination)**:
    * Выбор количества записей на странице: **10 / 25 / 50 / Все**.
    * Индикатор диапазона: `Показано 1–10 из 48 архивов`.
    * Кнопки перелистывания: `« Назад`, `1`, `2`, `3`..., `Вперёд »`. Дашборд всегда остаётся компактным и не превращается в «простыню» даже при многолетней истории бэкапов.
  * **Кликабельная сортировка по колонкам**:
    * Клик по заголовку сортирует список по возрастанию/убыванию: `Дата и время` (по умолчанию новые сверху), `Имя архива`, `Длительность`, `Исходный размер`, `Новых данных (Dedup)`, `Файлов`.
    * Визуальные индикаторы направления сортировки `▲` / `▼`.
  * **Быстрые фильтры по периоду**:
    * Кнопки-переключатели: `[ Все ]`, `[ 7 дней ]`, `[ 30 дней ]`, `[ Этот месяц ]`.
  * **Сквозной поиск и фильтрация**:
    * Поиск по имени или дате, а также фильтр репозитория (`Все`, `Docker`, `Immich`) действуют синхронно как в таблице, так и в календаре.

### 6. 📂 Проводник файлов срезов и прямое скачивание (Archive File Explorer)
* Кнопка **«Файлы»** у каждого архива в таблице открывает интерактивное дерево содержимого среза.
* Полноценная навигация по структуре каталогов внутри архива.
* Отображение размера, прав доступа, владельца и времени модификации каждого файла.
* **Прямое скачивание файлов из браузера**: клик по файлу инициирует его мгновенную потоковую распаковку (`borg extract --stdout`) и загрузку на клиентское устройство без необходимости заходить на сервер по SSH.

---

### 7. 🔍 Сравнение срезов (Archive Diff)
* Наглядное сравнение двух последовательных срезов резервных копий.
* Анализ изменений: какие файлы были добавлены, изменены или удалены, а также дельта изменения размера.

---

### 8. 📈 Интерактивные графики (ApexCharts)
* **Прирост новых данных (Инкременты):** Столбчатая диаграмма (МБ / ГБ), отображающая объем уникальных данных, записанных каждым отдельным бэкапом.
* **Длительность выполнения:** График времени создания снимков (в секундах) для контроля производительности дисковой подсистемы.
* **Фильтрация по репозиториям:** Быстрое переключение между агрегированной статистикой и отдельными репозиториями.

---

### 9. 🛡️ Мониторинг контура 3-2-1
Визуальные статус-бейджи смежных компонентов резервного копирования:
* **Целостность репозиториев (`borg check`):** Статус регулярных тестов целостности и журнал ошибок.
* **Облачная синхронизация:** Контроль ночной репликации в облачные хранилища (через `rclone` в Яндекс.Диск / S3 / WebDAV).
* **Пре-дампы баз данных:** Контроль создания горячих дампов СУБД (PostgreSQL, SQLite, Vaultwarden, Paperless, Authentik).
* **Холодные оффлайн-копии:** Статус еженедельных аппаратных снимков (rsync hardlinks на независимый носитель).

---

### 10. 📋 Генератор команд быстрого восстановления (CLI Helper)
В модальном окне архива генерируются готовые проверенные команды с подставленными путями:
* **FUSE-монтирование**: `borg mount /repos/borg_backup::archive /mnt/borg` (просмотр архива как обычной папки).
* **Точечное восстановление**: `borg extract --list /repos/borg_backup::archive path/to/file`.
* **Проверка среза**: `borg check -v --archives-only -a 'archive' /repos/borg_backup`.
* **Быстрое копирование**: Удобная кнопка «Скопировать» с поддержкой Clipboard API и HTTP-фоллбэком.

## 📦 Быстрый старт (Docker Compose)

### 1. Клонирование репозитория
```bash
git clone https://github.com/scanek/borg-dashboard.git
cd borg-dashboard
```

### 2. Настройка переменных окружения (`.env`)
Создайте файл `.env` в корне каталога:
```ini
# Часовой пояс
TZ=Europe/Moscow

# Путь к каталогу с репозиториями Borg на хосте
BORG_REPOS_HOST_PATH=/srv/dev-disk-by-uuid-278fc176-ec2b-4c6e-bdb2-a5d5882a892d

# Отображаемые пути на хосте (для генерации команд восстановления)
BORG_REPO_1_HOST_PATH=/srv/dev-disk-by-uuid-278fc176-ec2b-4c6e-bdb2-a5d5882a892d/borg_backup
BORG_REPO_2_HOST_PATH=/srv/dev-disk-by-uuid-278fc176-ec2b-4c6e-bdb2-a5d5882a892d/backups/immich-borg
```

### 3. Конфигурация `docker-compose.yml`
Убедитесь, что точки монтирования соответствуют вашей системе:

```yaml
services:
  borg-dashboard:
    build: .
    image: borg-dashboard:latest
    container_name: borg-dashboard
    restart: unless-stopped
    network_mode: host
    environment:
      - TZ=Europe/Moscow
      - BORG_UNKNOWN_UNENCRYPTED_REPO_ACCESS_IS_OK=yes
      - BORG_RELOCATED_REPO_ACCESS_IS_OK=yes
      - BORG_CACHE_DIR=/tmp/borg_cache
      - BORG_REPOS_HOST_PATH=${BORG_REPOS_HOST_PATH:-}
      - BORG_REPO_1_HOST_PATH=${BORG_REPO_1_HOST_PATH:-}
      - BORG_REPO_2_HOST_PATH=${BORG_REPO_2_HOST_PATH:-}
    volumes:
      # Репозитории Borg (требуется доступ на запись для lock-файлов Borg)
      - ${BORG_REPOS_HOST_PATH:-/srv/dev-disk-by-uuid-xxx}:/repos
      
      # Диски и пулы данных хоста для проводника и бэкапа (ТОЛЬКО ЧТЕНИЕ)
      - /srv:/srv:ro
      - /volume1:/volume1:ro
      
      # Логи резервного копирования (read-only)
      - /volume1/logs:/logs:ro
      
      # Инструкция по восстановлению (read-only, опционально)
      - /volume1/script/ИНСТРУКЦИЯ_ПО_ВОССТАНОВЛЕНИЮ.md:/app/docs/RECOVERY.md:ro
      
      # Персистентное хранилище настроек задач и кэша
      - ./data:/app/data
    healthcheck:
      test: ["CMD", "python3", "-c", "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8099/api/health')"]
      interval: 30s
      timeout: 10s
      retries: 3
```

> [!IMPORTANT]
> Обратите внимание: монтирование `- /srv:/srv:ro` и `- /volume1:/volume1:ro` выполнено с флагом **`:ro`** (Read-Only). Это полностью исключает случайное повреждение, изменение или удаление исходных файлов хоста при выполнении любых операций из интерфейса дашборда.

### 4. Запуск контейнера
```bash
docker compose up -d --build
```

Откройте веб-интерфейс в браузере: **`http://<IP-вашего-сервера>:8099`**.

## ⚙️ Тонкая настройка конфигурации

### Настройка репозиториев (`config.json`)
Файл `config.json` в корне проекта или в `./data/config.json` определяет список опрашиваемых репозиториев:

```json
[
  {
    "id": "docker",
    "name": "Docker & Контейнеры",
    "path": "/repos/borg_backup",
    "host_path": "/srv/dev-disk-by-uuid-xxx/borg_backup",
    "source": "/volume1/docker",
    "schedule": "Ежедневно в 01:00",
    "description": "Контейнеры, базы данных, пре-дампы и конфигурации"
  },
  {
    "id": "immich",
    "name": "Immich Фото & База",
    "path": "/repos/backups/immich-borg",
    "host_path": "/srv/dev-disk-by-uuid-xxx/backups/immich-borg",
    "source": "/volume1/immich",
    "schedule": "Ежедневно в 00:30",
    "description": "Медиатека фотографий и база PostgreSQL"
  }
]
```

### Настройка задач резервного копирования (`data/jobs.json`)
Задачи могут создаваться через веб-интерфейс или вручную в файле `data/jobs.json`:

```json
[
  {
    "id": "job-vaultwarden",
    "name": "Менеджер паролей Vaultwarden",
    "repo_id": "docker",
    "archive_prefix": "vaultwarden",
    "sources": [
      "/volume1/docker/vaultwarden"
    ],
    "exclude_patterns": [
      "*.tmp",
      "*.sock",
      "*cache*"
    ],
    "compression": "auto,zstd,6",
    "retention": {
      "keep_daily": 7,
      "keep_weekly": 4,
      "keep_monthly": 3
    },
    "schedule": {
      "enabled": true,
      "frequency": "daily",
      "time": "02:00"
    },
    "run_compact": false
  }
]
```

## 📡 Справочник API эндпоинтов

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/` | Главная страница веб-интерфейса |
| `GET` | `/api/status` | Полная сводка: KPI, репозитории, срезы, здоровье контура, прогноз диска |
| `POST`| `/api/refresh` | Запуск немедленного фонового пересканирования репозиториев |
| `GET` | `/api/health` | Проверка статуса сервиса (`{"status": "ok"}`) |
| `GET` | `/api/guide` | Текст руководства по восстановлению (Markdown) |
| `GET` | `/api/fs/browse?path=...` | Проводник каталогов сервера для выбора источников бэкапа |
| `GET` | `/api/jobs` | Список всех настроенных задач резервного копирования |
| `POST`| `/api/jobs` | Создание новой задачи бэкапа |
| `PUT` | `/api/jobs/{id}` | Обновление существующей задачи бэкапа |
| `DELETE` | `/api/jobs/{id}` | Удаление задачи бэкапа |
| `POST`| `/api/jobs/{id}/run` | Запуск задачи бэкапа (создание, ротация, логирование) |
| `POST`| `/api/actions/run` | Запуск произвольного сервисного действия (`check`, `break-lock`, `compact`) |
| `GET` | `/api/actions/status/{id}` | Опрос статуса и последних строк выполняемого действия |
| `GET` | `/api/actions/stream/{id}` | Потоковая передача вывода консоли в реальном времени (SSE) |
| `GET` | `/api/archive/files` | Список файлов внутри выбранного среза |
| `GET` | `/api/archive/download` | Прямое скачивание файла из исторического среза |
| `GET` | `/api/archive/diff` | Анализ различий между двумя архивами |

## 🔒 Безопасность и изоляция

1. **Защита рабочих данных (Read-Only Mounts)**: Диски сервера с рабочими данными контейнеров смонтированы в контейнер дашборда с параметром `:ro`. Контейнер дашборда физически не может повредить исходные данные.
2. **Изоляция репозиториев Borg**: Доступ на запись предоставляется исключительно к каталогу репозиториев Borg (`/repos`), так как создание срезов и установка кратковременных блокировок требуют записи в репозиторий.
3. **Отсутствие открытых секретов**: Все пути к дискам хоста и пароли репозиториев (если используются) изолированы в файле `.env`, который добавлен в `.gitignore` и никогда не попадает в публичный репозиторий.
4. **Безопасная работа с блокировками (Locks)**: Все вызовы чтения используют неблокирующие механизмы; для снятия блокировок предусмотрен безопасный инструмент `break-lock`.
