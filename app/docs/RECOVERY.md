# 📖 Руководство по аварийному восстановлению данных (Disaster Recovery)

> **Назначение документа:** Справочное руководство администратора по восстановлению данных из резервных копий BorgBackup в случае сбоя оборудования, повреждения файлов или развертывания системы с нуля.

---

## 🧭 1. Основные концепции восстановления BorgBackup

BorgBackup хранит данные в виде дедуплицированных блоков внутри репозитория. Для восстановления файлов доступны три основных способа:

1. **FUSE-монтирование (`borg mount`)** — подключение архива как обычной папки файловой системы для просмотра и точечного копирования через любой файловый менеджер или консоль.
2. **Прямое извлечение (`borg extract`)** — распаковка всего архива или указанных путей в текущую директорию с сохранением прав доступа и структуры каталогов.
3. **Восстановление через Web-интерфейс дашборда** — встроенный проводник файлов срезов с возможностью прямого скачивания одиночных файлов прямо в браузере.

## 🛠️ 2. Пошаговые команды восстановления

### Шаг 0. Установка BorgBackup на новую систему (при восстановлении с нуля)
Если вы разворачиваете сервер с нуля после полной замены оборудования:
* **Debian / Ubuntu / OpenMediaVault:** `sudo apt update && sudo apt install -y borgbackup`
* **Arch Linux:** `sudo pacman -S borg`
* **Любой Linux (автономный бинарник без зависимостей):**
  ```bash
  sudo wget https://github.com/borgbackup/borg/releases/latest/download/borg-linux64 -O /usr/local/bin/borg && sudo chmod 755 /usr/local/bin/borg
  ```

### Шаг 1. Проверка доступности репозитория
Перед началом восстановления убедитесь, что репозиторий доступен и не заблокирован:
```bash
# Просмотр списка архивов в репозитории
borg list /path/to/repository

# Если репозиторий заблокирован после аварии:
borg break-lock /path/to/repository
```

### Шаг 2. Вариант А: Монтирование архива как папки (FUSE)
Самый удобный способ, если требуется восстановить несколько конкретных файлов или папок:
```bash
# Создать точку монтирования
mkdir -p /mnt/borg

# Смонтировать конкретный архив
borg mount /path/to/repository::ARCHIVE_NAME /mnt/borg

# Либо смонтировать весь репозиторий со всеми срезами:
borg mount /path/to/repository /mnt/borg

# Скопировать нужные данные
cp -a /mnt/borg/path/to/file /destination/

# ОБЯЗАТЕЛЬНО размонтировать после завершения:
borg umount /mnt/borg
```

### Шаг 3. Вариант Б: Прямое извлечение файлов (Extract)
Для полного восстановления или извлечения больших массивов данных:
```bash
# Перейдите в каталог, куда будут извлекаться данные
cd /restore/target/dir

# Извлечь весь архив целиком:
borg extract -v --list /path/to/repository::ARCHIVE_NAME

# Извлечь конкретную директорию или файл:
borg extract -v --list /path/to/repository::ARCHIVE_NAME path/to/restore
```

## 🧪 3. Проверка целостности (Integrity & DR Test)

* **Быстрая проверка среза**:
  ```bash
  borg check -v --archives-only -a 'ARCHIVE_NAME' /path/to/repository
  ```
* **Полная проверка всех блоков репозитория**:
  ```bash
  borg check -v --progress /path/to/repository
  ```
* **Автоматический DR-тест**:
  Используйте кнопку **«Тест DR (Распаковка)»** в дашборде для симуляции извлечения и сверки контрольных сумм SHA-256 в изолированной песочнице.

---

## 💡 Рекомендации по безопасности 3-2-1
1. **3 копии данных**: рабочая система + основной Borg-репозиторий + внешняя/облачная реплика.
2. **2 разных носителя**: разные физические накопители (например, SSD рабочей системы и HDD пула бэкапов).
3. **1 копия вне площадки**: регулярная синхронизация (rclone / rsync) на удаленный сервер или в облако.
